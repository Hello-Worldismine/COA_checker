# 3분 시연 녹화 체크리스트

기획서 8장 "3분 시연 시나리오" 기준. 역할: **협력사** = `jaemin9905@naver.com`(네이버), **수신 Outlook** = `adm1nsubin@outlook.kr`, **담당자 알림 수신** = `alstnqls02@naver.com`(네이버).

## 1. 녹화 전 준비 (15분 전)

- [ ] 감시 프로그램·화면·결과 엑셀이 켜져 있으면 모두 닫기
- [ ] 초기화: `.venv\Scripts\python scripts\reset_demo.py --yes` → `[완료] … 샘플 PDF 5장 재생성` 확인
  - Outlook 메일의 `COA검증완료` 분류는 그대로 두므로 예전 시험 메일은 다시 처리되지 않음
- [ ] 클래식 Outlook을 직접 켜고 `adm1nsubin@outlook.kr` 받은편지함이 보이는지 확인
  - `jaemin9905@naver.com`이 수신 허용 목록에 있는지 확인 (정크로 빠지면 처리 안 됨)
- [ ] `config.toml`: `alert.mode = "send"`, `alert.to = ["alstnqls02@naver.com"]`, `test_senders`에 `jaemin9905@naver.com`
- [ ] `run_watcher.bat` 실행 → 첫 줄 `DB 파일: …\output\coa_history.db`, `최근 7일 미처리 COA 메일 0통 처리 완료. 새 메일을 기다립니다` 확인
- [ ] `run_app.bat` 실행 → 처리 현황 탭, 오늘 처리 `0건`, 맨 아래 DB 파일 경로가 감시 로그와 같은지 확인
- [ ] 브라우저 탭 미리 열기
  1. 네이버 메일(`jaemin9905`) **메일 쓰기** 창: 받는 사람 `adm1nsubin@outlook.kr`, 제목 `COA 10월 입고분 5건`, 첨부 `samples\` PDF 5장 (보내기 직전 상태로)
  2. Streamlit 화면 (`http://localhost:8501`)
  3. 네이버 메일(`alstnqls02`) 받은메일함 — 알림 메일 확인용 (다른 브라우저 또는 시크릿 창)
- [ ] 탐색기 창 2개: `samples\COA_Nippon_N2418_fail.pdf` + `data\spec_master.xlsx`(장면 1), `inbox\` 폴더(장면 3)
- [ ] 화면 녹화 준비: ZoomIt, 브라우저 확대 110~125 %, Windows 알림 끄기(방해 금지), 바탕화면 정리
- [ ] 리허설 1회 후 다시 `reset_demo` (리허설 메일은 분류가 달려 다시 처리되지 않음 → 녹화 때는 **새 메일**을 보냄)

## 2. 장면별 순서와 말할 문장

| 시간 | 화면·클릭 순서 | 말할 문장 |
| --- | --- | --- |
| 0:00~0:30 | `COA_Nippon_N2418_fail.pdf`와 `spec_master.xlsx`를 나란히. Water `50 ppm`, 규격 Moisture `0.003 %`를 ZoomIt으로 확대 | "QC 담당자는 이런 성적서를 하루 수십 건, 눈으로 규격과 대조합니다. 수분 50 ppm과 규격 0.003 %를 비교하려면 단위부터 머릿속으로 바꿔야 하죠." |
| 0:30~1:00 | 네이버(`jaemin9905`) 메일 쓰기 창 → 첨부 5장 보여 주고 **보내기** → 감시 콘솔 창으로 전환 | "협력사가 평소처럼 성적서 5장을 메일로 보냅니다. 담당자는 아무것도 누르지 않습니다." |
| 1:00~1:45 | 감시 콘솔에 `COA 수신: … → 부적합 (Moisture 50 ppm = 0.005 % > 0.003 %)` 줄이 차례로 뜸 → 탐색기 `inbox\날짜\`에 PDF 5장 → Streamlit 처리 현황(10초 안에 5건, 부적합 2·검토 필요 1·적합 2) → 네이버(`alstnqls02`)에 `[COA 부적합] … 외 2건` 알림 메일 열기 | "메일이 도착하자마자 첨부를 저장하고 판정했습니다. Iron 0.008 %는 상한 0.005 %를 넘어 부적합, 수분 50 ppm은 0.005 %로 자동 환산돼 0.003 % 초과로 부적합입니다. N.D.처럼 애매한 값은 추측하지 않고 '검토 필요'로 사람에게 넘깁니다." |
| 1:45~2:15 | Streamlit **판정 상세** → `Nippon Solvent / N2418` 선택 → 빨간 Moisture 행 → **결과 엑셀** 열기(빨간 행) → **통보서 초안** 열기 | "판정 근거가 항목별로 남고, 결과 엑셀과 협력사 통보서 초안까지 자동으로 만들어집니다. 통보서는 초안까지만, 발송은 사람이 확인한 뒤에 합니다." |
| 2:15~2:40 | **이력 검색** → Lot 칸에 `2418` 입력 → 결과 행 → **검색 결과 엑셀 다운로드** | "감사에서 석 달 전 Lot을 물어봐도, Lot 번호만 넣으면 판정 근거까지 몇 초 만에 찾습니다." |
| 2:40~3:00 | 처리 현황 탭으로 돌아와 지표 화면 | "메일 도착 즉시 판정, 건당 5~10분 걸리던 일이 예외 건 1분 확인으로 줄어듭니다. 하루 20건이면 연 580시간 이상입니다." |

기대 결과(정답지 `samples\expected.json`): A2401·N2417 적합, A2402 부적합(Iron), N2418 부적합(Moisture), N2419 검토 필요(Fe N.D.). 알림 메일은 메일 1통당 1통.

## 3. 실패 시 대체 장면

| 상황 | 대체 |
| --- | --- |
| 보낸 뒤 30초가 지나도 콘솔에 `COA 메일 감지`가 안 뜸 | Outlook 정크 메일 폴더 확인. 녹화 중이면 Streamlit **수동 업로드** 탭에 `samples\` PDF 5장을 끌어다 놓기 → 같은 판정표가 즉시 나옴. 말: "메일이 아닌 경로로 받은 성적서도 같은 엔진으로 판정합니다." |
| 콘솔에 `첨부가 아직 동기화되지 않아 미처리로 남김` | 60초 안에 자동 재확인. 기다리는 동안 장면 1 설명을 이어 가거나 수동 업로드로 전환 |
| 알림 메일이 네이버에 늦게 옴 | Outlook **보낸 편지함**의 `[COA 부적합] …` 메일을 열어 보여 주기 |
| 처리 현황이 안 바뀜 | 브라우저 새로고침(F5). 맨 아래 DB 파일 경로가 감시 로그 첫 줄과 같은지 확인 |
| 결과 엑셀이 안 열림/저장 실패 경고 | 엑셀 창이 이미 열려 있으면 닫기. 판정 상세의 판정표로 대신 설명 |
| 감시 프로그램 오류로 종료 | `run_watcher.bat` 다시 실행(시작 시 미처리 메일을 자동 처리). 그래도 안 되면 수동 업로드 |

## 4. 다시 녹화할 때

1. 감시 콘솔·화면에서 `Ctrl+C`, 결과 엑셀 닫기
2. `.venv\Scripts\python scripts\reset_demo.py --yes`
3. `run_watcher.bat`, `run_app.bat` 다시 실행 → 오늘 처리 `0건` 확인
4. 네이버에서 **새 메일**로 다시 보내기 (이미 보낸 메일은 `COA검증완료` 분류 때문에 다시 처리되지 않음)
