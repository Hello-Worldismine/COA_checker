# AI COA 자동검증기 프로젝트 기획서

Oct 22, 2026 · @Geonhee

## 1. 프로젝트 개요

**한 줄 요약:** 협력사가 Outlook으로 보낸 COA(시험성적서) 메일을 Python이 즉시 감지해 첨부 PDF를 저장하고 자동으로 읽어 사내 규격(Spec)과 대조하고, 부적합 원료가 입고되기 전에 담당자에게 경고하는 도구입니다.

**배경:** 품질관리(QC) 담당자는 매일 수십 장의 COA를 눈으로 사내 규격과 대조하고 ERP에 수기로 입력합니다. 소수점 한 자리, 단위(ppm과 %) 하나를 잘못 보면 불량 원료가 공정에 투입되어 수억 원대 손실로 이어질 수 있습니다.

**목표:**

1. COA 1건 처리 시간을 5\~10분에서 1분 이내(사람 확인 포함)로 줄인다.
2. 단위 환산과 규격 비교를 사람이 아닌 코드가 수행해 판정 실수를 없앤다.
3. 검증 결과를 배치·협력사·항목 단위로 저장해, 감사 대응 시 문서를 즉시 찾을 수 있게 한다.

**과제 범위(이번 발표):** Outlook 메일 자동 감지와 첨부 PDF 저장부터 단위 정규화, 규격 자동 판정, 결과 엑셀 생성, 부적합 알림 메일까지 사람 손 없이 이어지는 MVP를 시연합니다. ERP 연동과 스캔 PDF(OCR)는 확장 단계로 둡니다.

## 2. 현업 문제 정의 (Pain Point)

COA 검수의 위험은 느린 것보다 **한 번의 눈 실수가 대형 손실로 이어진다**는 데 있습니다. 아래 세 가지는 제조업 현장에서 흔히 일어날 수 있는 상황을 재구성한 예시 시나리오입니다.

| 유형 | 예시 상황 | 결과 | 근본 원인 |
| --- | --- | --- | --- |
| 수치 오독 | Iron 0.008%(기준 0.005% 이하)를 합격으로 착각 | 불량 원료 투입, 원료 폐기와 라인 정지 | 사람이 눈으로 비교, 피로도 |
| 단위 혼동 | 수분 50 ppm을 기준 0.003%(30 ppm)와 비교하다 환산 오류 | 부적합 원료로 만든 제품 납품, 리콜 | 협력사별 양식·단위 제각각, 수기 환산 |
| 조회 불가 | 감사에서 3개월 전 배치의 COA 요청 | 문서 1건 찾는 데 수 시간 | 파일명·폴더 비정형, 데이터로 저장 안 됨 |

세 사례의 공통 원인은 **COA가 데이터가 아닌 문서로만 존재한다**는 점입니다. 그래서 비교·환산·검색을 모두 사람이 해야 하고, 기존 RPA도 협력사마다 다른 양식을 처리하지 못합니다.

발표 전에 확인할 것: 소속 부서의 실제 COA 처리 건수(일/월)와 건당 소요시간을 넣으면 설득력이 크게 올라갑니다.

## 3. As-Is / To-Be 워크플로

```text
[As-Is] 모든 단계를 사람이 수행 · 건당 5~10분
  메일로 COA 수신 → PDF 열어 눈으로 대조 → ppm·% 단위 수기 환산 → ERP에 수기 입력 → 이상 시 메일 직접 작성

[To-Be] 메일 도착부터 판정까지 Python이 자동 수행 · 사람은 예외 건만
  Outlook 메일 즉시 감지 → 첨부 PDF 폴더 자동 저장 → 값·단위 추출 / 단위 정규화 → 규격 자동 판정(3단계) → 결과 엑셀·DB 자동 저장
                                                                          └─ 부적합·검토 필요 → 담당자 확인 + 알림 메일 (원본 PDF와 나란히)
```

메일이 도착하는 순간부터 저장·추출·판정까지 사람 손이 닿지 않고, 사람은 부적합·검토 필요 건만 확인합니다. 발표 양식의 "AI 적용 전/후 Workflow" 칸에 그대로 옮겨 쓸 수 있습니다.

## 4. 핵심 기능 정의

핵심 설계 원칙은 **AI는 읽기만, 판정은 Python 코드가** 하는 것입니다. AI가 숫자를 잘못 읽을 수는 있어도, 단위 환산과 합부 비교는 정해진 규칙대로만 수행되어 판정 근거를 항상 설명할 수 있습니다.

| # | 기능 | 내용 | MVP 포함 |
| --- | --- | --- | --- |
| F1 | 메일 감지 | Outlook에 새 메일이 오면 즉시 감지(NewMailEx 이벤트). 제목 'COA' 포함, 등록 협력사 도메인, PDF 첨부 조건으로 COA 메일만 선별 | 예 |
| F2 | 첨부 저장 | 첨부 PDF를 지정 폴더에 표준 파일명(수신일시\_협력사\_원본명)으로 자동 저장, 처리한 메일에 'COA검증완료' 분류 표시 | 예 |
| F3 | 누락 메일 보완 | 프로그램 시작 시 아직 처리하지 않은 COA 메일을 한 번 훑어 처리(꺼져 있던 동안 온 메일 대응) | 예 |
| F4 | 데이터 추출 | PDF 텍스트·표에서 협력사, 품명, Lot/Batch, 시험항목, 측정값, 단위를 추출(규칙 기반 + LLM 보조) | 예 |
| F5 | 항목명 매핑 | Iron, Fe, 철처럼 협력사마다 다른 항목명을 사내 표준 항목으로 연결(별칭 사전) | 예 |
| F6 | 단위 정규화 | ppm, %, mg/kg, ppb 등을 규격 단위로 자동 환산(1 ppm = 0.0001%) | 예 |
| F7 | 규격 판정 | 사내 Spec 마스터(엑셀)의 하한·상한과 비교해 적합 / 부적합 / 검토 필요 3단계 판정 | 예 |
| F8 | 결과 저장 | 검증 이력 DB 저장 + ERP 업로드 양식 엑셀 생성 | 예 |
| F9 | 알림 | 부적합·검토 필요 건은 담당자에게 Outlook 알림 메일(판정표 포함) 발송, 협력사용 부적합 통보서 초안 자동 작성 | 예(초안까지) |
| F10 | 현황 화면·이력 검색 | Streamlit 화면에서 처리 현황과 항목별 판정표 확인, 메일 외 경로용 수동 업로드, Lot·협력사·기간 검색(감사 대응) | 예 |
| F11 | 스캔 PDF 처리 | 텍스트가 없는 이미지 PDF는 OCR로 읽기 | 확장 |
| F12 | ERP 자동 입력 | 엑셀 업로드 대신 ERP에 직접 등록(API 또는 RPA) | 확장 |

**"검토 필요"를 두는 이유:** 항목을 못 찾거나, 단위를 모르거나, 숫자 형식이 이상하면(예: "<0.001", "N.D.") 코드가 추측하지 않고 사람에게 넘깁니다. 사람은 전체가 아니라 이 예외 건만 보면 됩니다.

## 5. 시스템 구성 및 기술 스택

언어는 **Python 3.12.5**로 통일하고, 아래 라이브러리는 모두 3.12용 배포판이 있습니다. 버전은 `requirements.txt`에 고정해 다른 PC에서도 같은 환경을 재현합니다.

| 계층 | 기술 | 역할 | 비고 |
| --- | --- | --- | --- |
| 언어·환경 | Python 3.12.5, venv | 전체 자동화 로직 | 가상환경으로 의존성 분리 |
| 메일 연동 | pywin32 (Outlook COM) | 새 메일 감지, 첨부 저장, 처리 완료 분류 표시, 알림 메일 발송 | Windows + 클래식 Outlook 필요 |
| 상시 실행 | Windows 작업 스케줄러 | 로그인 시 메일 감시 프로그램 자동 시작 | 별도 설치 없음 |
| GUI | Streamlit | 처리 현황, 판정표(부적합 강조), 수동 업로드, 이력 검색 화면 | 브라우저로 사용 |
| PDF 추출 | pdfplumber | PDF 텍스트와 표 추출 | 디지털 PDF용 |
| AI 보조 추출 | 사내 승인 LLM API(선택) | 규칙으로 못 읽는 양식을 JSON으로 구조화 | 켜고 끌 수 있게 설계 |
| 데이터 검증 | pydantic | 추출 결과의 형식(숫자, 단위, 필수 항목) 검사 | 형식 오류는 "검토 필요"로 |
| 단위 환산 | 자체 환산표 + Decimal(내장) | ppm·%·mg/kg 등 환산 | 환산 규칙을 코드로 고정 |
| 규격 마스터 | Excel(openpyxl, pandas) | 품목별 항목·하한·상한·단위·별칭, 등록 협력사 도메인 관리 | 현업이 직접 수정 가능 |
| 저장 | SQLite(내장 sqlite3) | 검증 이력, 처리한 메일 ID(중복 방지) | 서버 없이 파일 하나 |
| 출력 | openpyxl | 결과 엑셀, ERP 업로드 양식 | 부적합 셀 빨간색 |
| 로그 | logging(내장) | 메일별 처리 결과·오류 기록 | 누락 추적용 |
| 대안 경로 | watchdog | Outlook 연동이 막히면 규칙으로 저장된 폴더를 감시 | 판정 이후 흐름은 동일 |
| OCR | PaddleOCR 또는 Tesseract | 스캔 PDF 읽기 | 확장 단계, 3.12 호환 버전 사전 확인 |
| 테스트 | pytest | 단위 환산·판정 로직 테스트 | 판정 오류 방지의 핵심 |

### GUI를 만드는 게 좋은가? → 만드는 것을 권합니다

- **사용자가 개발자가 아닙니다.** QC 담당자는 명령어 창을 쓰지 않습니다. 메일 처리는 자동이어도, 처리 현황과 판정 결과를 확인하는 화면이 있어야 실제로 쓰입니다.
- **검사는 결국 사람이 확인합니다.** "검토 필요" 건을 화면에서 원본 PDF와 나란히 보고 승인하는 흐름이 필요합니다.
- **3분 시연에 유리합니다.** 빨간색 부적합 표시가 한 화면에 뜨는 장면이 평가자에게 가장 강하게 남습니다.

**왜 Streamlit인가:** Python 코드만으로 웹 화면을 만들어 하루 안에 MVP가 가능하고, 사내 서버 한 대에 올리면 여러 명이 브라우저로 접속합니다. PC별 설치가 없어 보안·배포 부담도 작습니다. 서버를 쓸 수 없는 환경이라면 PySide6 데스크톱 앱 + PyInstaller로 exe 배포가 대안입니다.

**코드 구조(화면과 로직 분리):** 두 프로그램이 같은 판정 엔진과 같은 DB를 공유합니다. 메일 감시 프로그램(mail\_watcher.py)은 백그라운드에서 상시 실행되고, Streamlit 화면(app.py)은 결과를 보여주기만 합니다.

```text
coa_checker/
├─ mail_watcher.py     # Outlook 감시: 감지 → 첨부 저장 → 판정 → 알림
├─ app.py              # Streamlit 화면: 현황·판정표·검색
├─ core/
│  ├─ outlook.py       # 메일 선별·첨부 저장·분류 표시·메일 발송
│  ├─ extractor.py     # PDF → 항목·값·단위 추출
│  ├─ mapper.py        # 항목명 별칭 매핑
│  ├─ units.py         # 단위 정규화
│  ├─ judge.py         # 규격 판정(적합/부적합/검토 필요)
│  └─ reporter.py      # 엑셀·DB 저장
├─ config.toml         # 저장 폴더, 협력사 도메인, 알림 수신자
├─ data/spec_master.xlsx
├─ inbox/              # 메일에서 저장된 COA PDF
├─ samples/            # 시연용 COA PDF
└─ tests/test_units.py
```

## 6. 기대 효과

건당 처리시간이 **5\~10분에서 1분 이내**로 줄고, 사람은 예외 건만 확인합니다. 아래 수치는 가정이므로 발표 전에 실제 처리 건수로 바꿔 넣으세요.

| 구분 | As-Is (수작업) | To-Be (자동검증기) |
| --- | --- | --- |
| 판정 시점 | 담당자가 메일함을 열어 처리할 때 | 메일 도착 즉시(수 초 내) |
| 건당 소요시간 | 5\~10분 (첨부 열기 + 대조 + ERP 입력) | 사람 작업 0분, 예외 건만 확인 1분 이내 |
| 단위 환산 | 담당자 암산·엑셀 수식 | 코드로 고정된 환산 규칙 |
| 판정 근거 | 합격 도장만 남음 | 항목별 측정값·환산값·기준이 이력으로 남음 |
| 부적합 후속 조치 | 메일·통보서 수기 작성 | 알림 메일과 통보서 초안 자동 생성 |
| 문서 보관·감사 대응 | 메일함·폴더·종이 철을 눈으로 탐색 | 표준 파일명 자동 보관, Lot·협력사·기간 검색 수 초 |
| 수행 주기 | 일 (입고 건마다) | 일 (메일 수신 시 자동) |

**연간 절감 시간 계산식(예시):** 일 20건 × 건당 7분 절감 × 연 250일 = 약 583시간/년. 실제 건수를 넣으면 바로 다시 계산됩니다.

**정성 효과:** 시간 절감보다 큰 가치는 리스크 차단입니다. 부적합 원료 한 건이 투입되면 원료 폐기, 라인 정지, 고객 클레임으로 이어질 수 있어, 입고 단계에서 자동으로 걸러내는 것 자체가 품질 방화벽 역할을 합니다.

## 7. 리스크와 대응

| 리스크 | 내용 | 대응 |
| --- | --- | --- |
| Outlook 버전 | 새 Outlook(New Outlook for Windows)은 COM 연동을 지원하지 않음 | 클래식 Outlook에서 운영, 회사 PC 버전을 가장 먼저 확인 |
| 회사 보안 정책 | 외부 프로그램의 Outlook 접근이 차단될 수 있음 | 막히면 Outlook 규칙으로 첨부를 폴더에 저장하고 폴더 감시(watchdog)로 대체 |
| 메일 누락 | PC나 프로그램이 꺼져 있는 동안 온 메일은 이벤트를 못 받음 | 시작 시 미처리 메일 재탐색(F3), 작업 스케줄러로 자동 시작 |
| 중복 처리 | 같은 메일을 두 번 판정 | 메일 ID를 DB에 기록, 처리 완료 분류 표시 |
| 오탐·미탐 | COA가 아닌 메일을 잡거나, 제목 없는 COA를 놓침 | 협력사 도메인 + PDF 첨부 조건 병행, 판독 실패 시 "검토 필요" |
| 추출 오류 | AI나 파서가 숫자·항목을 잘못 읽을 수 있음 | 판정은 코드가 수행, 애매한 건은 "검토 필요"로 분류, 원본 PDF와 나란히 확인 |
| "100% 정확"이라는 기대 | 자동화도 오류가 있을 수 있음 | 발표에서는 "사람의 최종 확인을 돕는 이중 검증"으로 표현 |
| 데이터 보안 | COA는 협력사 영업 정보로, 외부 AI 서비스 전송이 금지될 수 있음 | 기본은 규칙 기반 추출, LLM은 사내 승인 모델만 연결, 연결 끄기 옵션 제공 |
| 스캔 PDF | 텍스트가 없는 이미지 PDF는 바로 못 읽음 | MVP에서는 "검토 필요" 처리, 확장 단계에서 OCR 도입 |
| 특수 표기 | "<0.001", "N.D.", "±0.2" 같은 값 | 표기별 규칙을 테스트로 고정, 모르는 표기는 검토 필요 |
| 규격 마스터 관리 | Spec이 바뀌면 판정도 바뀌어야 함 | 엑셀 마스터를 현업이 직접 수정, 판정 이력에 적용 Spec 버전 기록 |
